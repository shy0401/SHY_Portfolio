## 프로젝트 개요

실습용 바이너리와 대회형 리버싱 문제를 대상으로 정적·동적 분석 루틴을 반복 학습하고, 분석 근거를 재사용 가능한 형식으로 정리하는 프로젝트입니다. 목표는 “정답 문자열 찾기”가 아니라 실행 파일의 입력 처리, 분기, 메모리 변화, 성공 조건을 근거 중심으로 설명하는 것입니다.

BCG 해킹대회 `Reversing_1 - Buffer_Overflow` 풀이 기록을 기반으로 입력 길이, 성공 문자열, 파일 구조, 실행 결과를 함께 분석하는 방식으로 구성했습니다.

## 수행 내용

- 함수 흐름, 호출 구조, 문자열 패턴 추적 절차 정리
- 간단한 패킹·난독화 케이스 해제 실습
- 분석 노트 템플릿 통일 및 기록 규칙 수립
- Buffer Overflow 문제를 입력 길이, 성공 문자열, 경계값 관점으로 재정리
- 파일 기본 정보, 문자열, 분기 조건, 실행 결과를 분리해 분석하는 표준 루틴 구성
- 정적 단서와 동적 검증 결과를 분리해 기록하는 분석 노트 구조 설계

## 분석 루틴

| 단계 | 확인 항목 | 산출물 |
| --- | --- | --- |
| 1. 파일 기본 정보 | 파일명, 확장자, 크기, 해시, 실행 가능 여부 | 분석 시작 기록표 |
| 2. 정적 단서 | 문자열, 성공/실패 메시지, 의심 API, 파일 시그니처 | 단서 목록 |
| 3. 입력 처리 | 입력 길이, 특수문자, 반복 문자, 경계값 | 재현 조건 기록 |
| 4. 동적 관찰 | 레지스터, 스택, 메모리, 분기 결과 | 디버거 관찰표 |
| 5. 행위 해석 | 성공 조건, 취약 동작, 보안적 의미 | 분석 요약 |
| 6. 보고서화 | 단서, 검증, 결론, 한계점 | 리버싱 분석 노트 |

## 프로젝트 산출물

- 리버싱 분석 노트 템플릿
- Buffer Overflow 문제 재해석 기록
- 정적/동적 분석 체크리스트
- 포렌식 연계 파일 구조 분석 메모
- 사이버수사형 설명을 위한 비전문가 요약문

## 결과

리버싱 학습을 단편 지식이 아닌 체계적 루틴으로 전환해,  
향후 웹 보안 및 포렌식 프로젝트와 자연스럽게 연계 가능한 기반을 만들었습니다.

## 다음 개선 계획

- 간단한 실습 바이너리를 직접 구성해 입력 검증 전후 차이 비교
- 패킹/난독화 기초 사례를 별도 노트로 분리
- 포렌식 타임라인과 연결해 실행 파일이 남기는 흔적 정리
